## Изменения 1.1.5 — уточнение диагностики

Для статуса №5 подробная диагностика пробелов, невидимых символов и похожих букв выводится только если артикулы совпадают после устранения разрешённых скрытых различий в диагностических копиях. Например, `132604` и `Hammer, 4+128, без ОС + ПО Старт` считаются явно разными: выводятся исходные артикулы и ID без лишних сообщений о пробелах. Поиск и обновление не меняются.

## Изменения 1.1.4 — согласованные правила

1. **Проверка артикулов на даты до сверки.** После загрузки XLSX и выбора колонки артикула можно нажать «Проверить артикулы Excel». Показываются номера проблемных строк и причины. Это самостоятельная проверка, не обращающаяся к каталогу Битрикс. Она не исправляет исходный XLSX. При основной сверке проверка дат выполняется независимо от нажатия кнопки.
2. **Безопасность.** Если ячейка артикула сохранена как дата (Excel `t=d` или числовое значение с форматом даты), строка всегда имеет результат «Пропустить», независимо от одного из девяти присвоенных статусов. Если по GUID обнаружен товар, в причинах указываются его ID и артикул. Пример: «Артикул Excel сохранён как дата: 01.11.2026 (числовое значение 46327). Возможно автоматическое преобразование артикула Excel в дату. GUID найден у товара ID 240345 с артикулом NOV-01.» Числовые артикулы без формата даты по-прежнему только предупреждаются.
3. **Дополнительная диагностика статуса №5.** При статусе «GUID найден у другого артикула на сайте» программа сообщает о различии в количестве пробелов, неразрывных и невидимых символах, похожих кириллических/латинских буквах, если они обнаружены. Очевидные отличия не исправляются. Сообщение «GUID занят другим товаром» применяется только при реальном конфликте GUID с товаром, отличным от совпавшего по артикулу.
4. **Интерфейс.** Инструкция «Порядок подготовки и сверки Excel с Битрикс» свёрнута по умолчанию, содержит шесть шагов с новым шагом проверки дат. Сводка статусов по-прежнему содержит девять строк и четыре колонки; для №5 и №7 добавлены пояснения. Под таблицей — общее правило блокировки артикулов-дат.
5. **Настройки и вывод.** «Исключить строки с нулевой или пустой ценой» включено по умолчанию; «Преобразовать артикулы в текст в новом XLSX (необязательно)» выключено. В версии 1.1.6 вместо предварительной таблицы используется журнал сверки; пакет обновления по-прежнему 25 товаров.

**Рекомендуемый порядок (6 шагов):** исключить строки без цены → проверить дубли → проверить артикулы на даты → выполнить предварительную сверку → проверить результаты → запустить обновление.

**Ограничение:** исходный артикул вида `NOV-1` не восстанавливается автоматически из даты и не приводится к `NOV-01`. Преобразование артикулов в текст в подготовленном XLSX не восстанавливает значения, уже испорченные Excel.

**Проверка:** PHP-файлы проверены командой `php -l`. Локальная PHP-среда не содержит расширения `zip`, поэтому полноценный тест чтения XLSX и интеграционное тестирование с Битрикс не проводились. Перед массовым запуском проверьте несколько товаров на тестовой копии.

## Правила версии 1.1.3 (приоритет над описаниями прежних версий)

- **Артикул — основной ключ.** Если найден ровно один товар по артикулу, GUID Excel свободен от принадлежности другим товарам и проверки пройдены, можно записать GUID Excel в `XML_ID`, включая замену значения `0` или другого существующего GUID. Перед каждой записью принадлежность GUID и сопоставление проверяются повторно.
- **Запреты:** дубль артикула в проверяемом Excel, несколько товаров с артикулом на сайте, GUID Excel уже занят другим товаром, отсутствие артикула или обязательного GUID, ошибки цены/каталога. Диагностика по GUID при пропуске сохраняется. Артикул и название не изменяются.
- **Статусы сверки (9):** «Готов к обновлению», «GUID уже совпадает», «Дубль артикула в Excel», «Дубль артикула на сайте», «GUID найден у другого артикула на сайте», «GUID занят другим товаром на сайте», «Товар не найден на сайте», «Нет артикула в Excel», «Проблема с ценой в Excel». Последний объединяет пустую, нулевую и некорректную цену; конкретная ошибка остаётся в «Причинах». Пустой GUID не является отдельным видимым статусом или причиной, но блокирует запись. Конфликт повторного GUID внутри Excel остаётся защитной проверкой, а не отдельным статусом.
- **Приоритет:** дубли артикула важнее проблемы цены. Если строка одновременно имеет дубль и плохую цену, статус — «Дубль артикула в Excel», а ошибка цены указывается в причинах.
- **Подготовка:** при включённом исключении пустых и нулевых цен сначала исключаются эти строки, затем на оставшихся определяется число дублей и создаётся готовый XLSX дублей. Скачивание отдаёт сохранённый файл, не пересчитывая дубли. Без исключения цен дубли определяются по всему исходному набору.
- **Сводка:** раскрывающийся раздел «Правила обновления и причины пропуска» показывает каждый из девяти статусов в таблице с колонками «Статус», «Результат», «Условия сверки», «Действие». Значки не требуются. Внутренние технические проверки в сводке не перечисляются.

## Установка

Архив содержит каталоги `bitrix/` и `local/`: распакуйте **их содержимое в корень сайта**, чтобы файлы оказались по адресам:

- `/bitrix/admin/update_guid.php`
- `/local/bitrix-guid-tool/lib/Core.php`, `Excel.php`, `CoreStats.php`, `Store.php`
- `/local/bitrix-guid-tool/CHANGELOG.md` — история изменений, отображаемая в админке

Не создавайте дополнительную папку `bitrix-guid-tool` в корне сайта при распаковке. Предварительно сохраните копию старого `/bitrix/admin/update_guid.php` и БД. Требуются PHP UTF-8, модули `iblock`, `catalog`, расширения `zip`, `SimpleXML`, `libxml`. В родительском каталоге `DOCUMENT_ROOT` сервер создаёт закрытое хранилище `.bitrix-guid-tool-private-…` с правами `0700`. Проверьте доступ на запись и что папка действительно недоступна по HTTP.

Выберите профиль `gk-mact.ru` (товары 384 / SKU 386) или `prom-mact.ru` (товары 488 / SKU 490). Выбор профиля не заменяет проверку соответствия инфоблоков вашему сайту.

## Порядок работы

Рекомендуется выполнять этапы по порядку. **До запуска обновления изменения на сайте не производятся.**

### 1. Исключить товары без цены

Удалите из рабочего Excel строки с пустой или нулевой ценой. Сделать это можно двумя способами:

- **Вручную:** удалить строки в Excel перед загрузкой.
- **Через подготовку:** загрузить исходный XLSX, выбрать колонки «Артикул», «GUID», «Название», «Цена» и первую строку данных, отметить «Исключить строки с нулевой или пустой ценой» и нажать «Применить подготовку».

Исходный файл не изменяется; подготовленный XLSX можно скачать. Обрабатывается первый лист XLSX (до 10 МБ и 20 000 строк).

**Результат:** подготовленный Excel с товарами, у которых есть цена.

### 2. Проверить и устранить дубли артикулов в Excel

После исключения строк без цены скачайте **«Дубли XLSX»** и проверьте повторяющиеся артикулы. Рекомендуется исправить исходные данные и повторно загрузить Excel до сверки. Если дубли останутся, предварительная сверка всё равно выполнится, но все строки с повторяющимися артикулами получат статус **«Дубль артикула в Excel»** и будут пропущены при обновлении.

**Результат:** желательно получить Excel без дублей, чтобы больше товаров могли пройти сверку и обновление.

### 3. Выполнить предварительную сверку с Битрикс

Выберите профиль сайта и запустите полную сверку без записи. Программа ищет товары и торговые предложения по артикулу, проверяет GUID (`XML_ID`), выявляет конфликты и формирует статусы. **Данные сайта при сверке не изменяются.** При желании можно сверить исходный файл без подготовки.

**Результат:** таблица с ID найденных товаров, статусами и причинами пропуска.

### 4. Проверить результаты сверки

Изучите количества **«К обновлению»** и **«Пропустить»**, таблицу по 100 строк и **«Предварительный XLSX»**. Особое внимание уделите дублям артикулов на сайте и конфликтам GUID. Исправьте проблемы и при необходимости повторите сверку. Расшифровка девяти пользовательских статусов доступна в раскрывающемся разделе **«Логика сверки по каждому статусу»**.

**Результат:** проверенный список товаров, которые разрешено обновлять.

### 5. Запустить обновление

Выполняйте обновление вручную партиями по 25 строк: **«Обновить первые 25»**, затем **«Обновить следующие 25»**. Программа изменяет предусмотренные поля (`XML_ID`, цену, `ACTIVE`, `QUANTITY`, `KOD_IZ_1C`), но не меняет артикул и название. Скачайте **«Итоговый XLSX»** после обработки.

**Результат:** обновлённые товары, итоговый отчёт и сохранённая история операции.

### Дополнительные возможности

- **Сохранение состояния:** после каждого пакета состояние хранится на сервере; можно продолжить обработку после перезагрузки страницы.
- **История обновлений:** отчёты сохраняются отдельно по запускам бессрочно до ручного удаления. Удаление отчёта не меняет товары. При остановке доступен неполный итоговый отчёт.
- **Подготовка Excel:** можно преобразовать артикулы в текст в новом XLSX. Если подготовка не выполнялась, сверка исходного Excel включает строки с пустыми/нулевыми ценами и дубли, которые могут быть пропущены.

**Безопасность:** перед массовой записью сделайте резервную копию Битрикс, остановите обмен с 1С и конкурирующие импорты. Автоматического отката нет; возможна частичная запись. Перед каждой записью повторно проверяется занятость GUID другим товаром.

| `Нет артикула` | Пропустить | Артикул пустой; GUID проверяется для диагностики, обновление запрещено. |
| `Пустой GUID` | Пропустить | GUID Excel отсутствует. |
| `Пустая цена` / `Цена 0` / ошибка цены | Пропустить | Цена не подходит для обновления. |
| `Один GUID у разных артикулов Excel` | Пропустить | В Excel один GUID у разных артикулов, требуется ручная проверка. |
| `GUID занят другим товаром: …` | Пропустить | Артикул указывает на один товар, GUID — на другой. Сравнить товары и выяснить причину. |
| `Нет записи каталога` / `Несколько базовых цен для количества 1` | Пропустить | Проблема с каталогом или базовой ценой товара, нужна ручная проверка. |
| Ошибка ключевой ячейки (`Артикул: …`, `GUID: …`, `Цена: …`) | Пропустить | Формула, ошибка Excel или неподдерживаемое значение; исправить исходный файл. |

Числовой артикул — только предупреждение в «Причинах» и сам по себе не запрещает обновление. `XML_ID = 0` продолжает обрабатываться по существующему правилу как заполненное значение.

## Статус и результат — как понимать

**«Статус»** — вывод сверки, **«Причины»** — детали и предупреждения, **«Результат»** — решение до запуска или фактический исход записи.

| Статус / причина | Пример | Результат до запуска |
|---|---|---|
| `Готов к обновлению` | Артикул найден однозначно, `XML_ID` пуст, цена положительная | `К обновлению` |
| `GUID уже совпадает` | GUID Excel равен `XML_ID` на сайте; остальные поля всё равно обновляются | `К обновлению` |
| `Числовой артикул: проверьте возможную потерю ведущих нулей` | Excel хранит `135112` как число. Это **предупреждение в «Причинах»**, не блокировка; при остальных корректных проверках основной статус остаётся `Готов к обновлению` или `GUID уже совпадает` | `К обновлению`, если других ошибок нет |
| `Найден по GUID, артикул отличается` | Excel `MS310`, сайт ID `267881` с артикулом `00-09912036`, GUID совпал. В причинах видны оба артикула и ID | `Пропустить` |
| `Не найден на сайте` | Артикул не найден, а GUID не дал однозначного объяснения | `Пропустить` |
| `GUID занят другим товаром` | GUID принадлежит ID `267915`, но по артикулу найден другой товар | `Пропустить` |
| `Дубль артикула в Excel` | Две строки `26х26крПГЛ10000` с разными GUID | `Пропустить` для обеих |
| `Дубль артикула на сайте` | Один артикул найден у нескольких элементов | `Пропустить` |
| `Другой GUID — ручная проверка` | Артикул найден, но заполненный GUID сайта отличается от Excel | `Пропустить` |
| `Нет артикула` | Пустая ячейка артикула | `Пропустить` |
| `Цена 0`, `Пустая цена`, `Некорректная цена` | Цена `0`, пустая или неподдерживаемый формат | `Пропустить` |

| `GUID должен быть текстом` | GUID Excel оказался числом | `Пропустить` |
| `Формула: замените значением` | В одной из ключевых ячеек Excel находится формула | `Пропустить` |

**Результаты после начала записи:** `К обновлению` — ещё не дошла очередь; `Обновлено` — операция подтверждена; `Пропущено: …` — повторная проверка выявила препятствие; `Ошибка/частичная запись: …` — нужно вручную проверить состояние товара; `Запись начата — проверить` — попытка могла оборваться, автоматически не повторяется.

### Числовые артикулы и пробелы

При поиске `135112` как число и как текст сопоставляются с одним артикулом. Пробелы **по краям** артикула удаляются автоматически при сверке, даже без подготовки. Исходное значение остаётся в колонке исходного Excel в отчётах. Вид `1.24E+12` может быть только отображением Excel; если цифры действительно сохранены, это не ошибка. Если Excel уже потерял ведущие нули или точность длинного числа, галочка преобразования в текст не восстановит их. Галочка влияет только на подготовленный XLSX.

### Отчёты

- **Подготовленный XLSX:** только если применялась подготовка; исключённые строки убраны, артикулы могут быть записаны как текст.
- **Предварительный XLSX:** только строки, участвовавшие в сверке: после применения подготовки — оставшиеся строки, при прямой проверке — все исходные строки. Результаты зафиксированы до первой записи и не меняются при последующих пакетах.
- **Итоговый XLSX:** те же строки, что в сверке, с фактическими результатами обновления; доступен после первого пакета, при остановке и после завершения.

## Что обновляется

Для найденного по артикулу товара или SKU: `XML_ID` (только если пуст или совпадает), базовая цена `RUB`, `ACTIVE=Y`, свойство `KOD_IZ_1C=Y`, количество `100`. **Название и артикул на сайте не изменяются.** Если заполненный GUID отличается, строка пропускается. Дубли Excel не выбираются автоматически.

## История и хранение

При первом пакете создаётся отдельный ID запуска, записываются начало, профиль и ID администратора; после пакетов архив обновляется, по завершении записывается время окончания. Архивные XLSX лежат в закрытом серверном каталоге отдельно от текущего состояния. Можно выбрать несколько отчётов и удалить их после подтверждения; товары не затрагиваются. При обрыве запроса текущее состояние может сохраниться раньше, чем архивный XLSX; откройте страницу и проверьте отчёт перед сбросом задания.

## Возможный функционал в будущем (не реализован)

1. Предлагать **изменить артикул на сайте по совпавшему GUID** (например, сообщение `Не найден на сайте; GUID занят другим товаром: 267915`) только после отдельного согласования проверок и подтверждения.
2. Для **пустого артикула** добавить резервную проверку по GUID или коду 1С с правилами однозначного сопоставления. Сейчас такие строки не обновляются.

## Ограничения

Проверяйте свойства `CML2_ARTICLE` и `ARTICLE`, настройку списка `KOD_IZ_1C` (`XML_ID=Y`), базовую цену и связи SKU. Формулы XLSX не вычисляются. После обрыва во время отдельной записи повторять её автоматически небезопасно: нужна ручная проверка. Полная интеграционная проверка этой сборки на Битрикс ещё не выполнена.

## Изменения 1.1.1 — подготовка и предварительная таблица

- В подготовке только две необязательные галочки: «Исключить строки с нулевой или пустой ценой» и «Преобразовать артикулы в текст в новом XLSX». Исключение пустых артикулов и удаление дублей отсутствуют.
- «Проверить подготовку» только анализирует загруженный Excel. Статистика исходных проблем показывается всегда: всего строк, нулевая/пустая цена, пустой артикул, пробелы по краям, строки с дублями. Отдельно показывается прогноз «будет исключено» и «останется» по выбранным галочкам.
- Под статистикой появляется таблица всех строк с дублирующимися артикулами (поиск по артикулу, по 100 строк на странице): строка Excel, артикул, GUID Excel, цена Excel. Кнопка «Скачать дубли XLSX» сохраняет все исходные столбцы и номер строки. Дубли не удаляются.
- «Применить подготовку» создаёт подготовленный XLSX, исходный файл не меняется. «Сразу проверить без подготовки» проверяет исходный набор без исключения строк.
- Предварительная таблица теперь показывает 12 столбцов: Строка, Артикул Excel, Название Excel, GUID Excel, Цена Excel, ID сайта, Тип, Название сайта, XML_ID сайта, Статус, Причины, Результат. Название Excel читается из выбранной колонки «Название», независимо от наличия товара в Битрикс.
- Примеры: пустой артикул и GUID, обнаруженный на сайте → «Найден по GUID, артикул отличается» и «Пропустить»; два одинаковых артикула с разными GUID → обе строки «Пропустить», но GUID каждого проверяется; цена 0 → «Пропустить» при сверке, даже если не исключалась подготовкой; числовой артикул → предупреждение, но не автоматический пропуск.
- Двухуровневая шапка, показ дополнительной информации о конфликтующем товаре, изменение артикула по GUID и разрешение обновления при пустом артикуле остаются возможностями будущих версий.

Версия выпускается без суффикса «test». Работа на реальном сервере Битрикс должна быть проверена до массового обновления.


## Уточнение 1.1.7 — фильтрация журнала сверки

- «Все проблемы» по умолчанию показывает строки с исходным результатом «Пропустить», в том числе строки со статусами №1/№2, заблокированные проверкой артикула-даты.
- Выпадающий фильтр предлагает все 9 статусов, включая №1 «Готов к обновлению» и №2 «GUID уже совпадает». По умолчанию «Все проблемы» показывает только строки с исходным решением «Пропустить». При выборе статуса показываются все строки этого статуса независимо от результата.
- Поиск применяется ко всем строкам выбранного статуса, а в режиме «Все проблемы» — ко всем проблемным строкам. Ограничение 200 строк действует только после поиска и фильтрации.
- Полный предварительный XLSX содержит все строки без ограничения 200.
- При пакетном обновлении для журнала используется исходное решение о пропуске, а не изменившийся результат выполнения.
