**Решение:** создавать **новую чистую кодовую базу**, не встраивая весь новый функционал поверх v1.11. При этом **v1.11 не удалять и не изменять**: она остаётся резервной рабочей версией и источником проверенных подходов к Bitrix API.

Принципы реализации:

- Сначала изучить архив v1.11: подключение модулей Битрикс, авторизация и права администратора, выбор сайта/инфоблоков, поиск по артикулу, работу с простыми товарами и SKU, запись GUID, цен, остатков и свойств.
- Не переписывать ради переписывания уже проверенные операции с Битрикс; адаптировать их к новой структуре после проверки корректности.
- Разделить логику на понятные части: **импорт и подготовка Excel → сверка → план обновления → пакетная запись → отчёты**. Интерфейс может оставаться компактным PHP-инструментом; многосервисная архитектура не требуется.
- Обеспечить изоляцию данных каждого сайта и задания, хранение прогресса и запрет параллельных обновлений одного сайта.
- Не требовать cron, фонового воркера, очередей или дополнительных серверных служб; обновление идёт последовательными запросами из открытой страницы.
- Сохранять совместимость с фактической средой Битрикс, версиями PHP и доступными библиотеками XLSX; выбор библиотек и точная структура файлов уточняются после анализа v1.11.
- **Не заменять действующий v1.11 до проверки 1.1.0.** Сначала проверить импорт/сверку без записи, затем тестовые 5–10 товаров и только после этого массовое обновление.

Это **предварительно выбранная стратегия**: если анализ исходников обнаружит критические ограничения, технические детали можно уточнить, не меняя согласованную бизнес-логику без отдельного обсуждения.

## 3. Общий сценарий

1. Выбор сайта, загрузка XLSX из 1С.
2. Выбор колонок Excel: **артикул, GUID, наименование, цена** (по заголовкам). Показ первых строк для контроля соответствия.
3. На **одной странице** доступны два пути: необязательная подготовка Excel по выбранным опциям (просмотр изменений → подтверждение → подготовленный XLSX) **или сразу предварительная сверка исходного файла**. Оригинал не изменяется.
4. При необходимости скачивание подготовленного XLSX.
5. **Полная предварительная сверка** подготовленных строк с Битрикс, без записи в каталог.
6. Просмотр сводки, фильтрация/поиск, скачивание предварительного XLSX.
7. Ручной запуск **каждого** пакета до 25 разрешённых записей кнопкой «Обновить первые 25» / «Обновить следующие 25» (для последнего пакета — фактический остаток). Автоматического запуска следующего пакета и кнопок «Пауза / Продолжить» нет. Прогресс сохраняется на сервере; можно остановить обработку.
8. Просмотр результата и скачивание итогового XLSX.

Повторно загружать файл между этапами не требуется.

## 4. Подготовка Excel — опции с галочками

| Опция | По умолчанию | Правило |
|---|---|---|
| Исключать строки с ценой 0 или пустой ценой | Включена | Такие строки не участвуют в сверке/обновлении |
| Исключать строки с пустым артикулом | Включена | Если опцию выключить — строка остаётся для сверки со статусом «Нет артикула» |
| Убирать дубли артикулов | Выключена | Нельзя произвольно оставлять первую строку. До определения и подтверждения безопасного правила дубли **не удаляются автоматически**, а передаются в сверку со статусом конфликта |
| Преобразовать артикулы в текст в подготовленном XLSX | Выключена | Необязательное преобразование типа ячеек артикула в текст; не восстанавливает уже утраченные ведущие нули или точность |

**Не добавлять** отдельную опцию удаления артикулов со значением `0`.

Дополнительные правила:
- Не преобразовывать GUID и остальные колонки на этапе подготовки. **Независимо от подготовки** при поиске товара и проверке дублей автоматически убирать пробелы **по краям** артикула; не менять внутренние символы, регистр и исходные значения в отчёте.
- Числовой тип ячейки артикула — **предупреждение**, а не самостоятельное основание для пропуска. Поиск выполняется по корректно прочитанному строковому представлению значения. Отображение вида `1.24E+12` может быть лишь форматом показа: не считать это ошибкой без проверки сохранённого значения. Если Excel уже потерял ведущие нули или точность, восстановление не выполнять.
- Цены корректно читать из допустимых числовых представлений, включая десятичную запятую и пробелы-разделители тысяч. Нельзя угадывать неоднозначные/повреждённые значения: отмечать как ошибку.
- Преобразование числовой ячейки Excel в текст само по себе не восстанавливает утраченные ведущие нули. При неоднозначности — предупреждение, а не выдуманное значение.
- Нормализация артикула должна быть согласована с поиском и выявлением дублей в Битрикс: одно правило сравнения с обеих сторон.
- До применения показать числа: всего строк, исключено по каждой причине, нормализовано, осталось. Если строка подпадает под несколько правил, исключить её один раз и корректно посчитать итоги.
- После подтверждения доступен отдельный **подготовленный XLSX** с сохранением исходных колонок в исходном порядке, но без исключённых строк.
- Оригинальный файл не изменяется. Для отчётности сохранить сведения обо **всех исходных строках**, в том числе исключённых при подготовке.
- Если опция обработки дублей будет включена, до реализации необходимо определить безопасное правило с явным предварительным просмотром. До этого допустимо показывать найденные дубли, но **не удалять их**.

## 5. Сопоставление товаров

- Сопоставление выполняется по артикулу.
- Обрабатывать **простые товары** и **сами торговые предложения (SKU)**.
- **Не менять родительские товары с торговыми предложениями**: они не являются целевыми элементами привязки GUID.
- При поиске учитывать все целевые элементы выбранного сайта и находить дубли артикулов среди простых товаров и SKU.
- Если на сайте по одному артикулу найдено несколько целевых элементов — не обновлять ни один, даже если у одного GUID совпадает.
- Если в Excel несколько строк с одним нормализованным артикулом — все затронутые строки считать конфликтными, не обновлять автоматически.
- Если GUID из Excel уже занят другим элементом сайта — блокировать запись. Если элемент обнаружен по GUID, но артикул из Excel не совпадает с артикулом этого элемента, показывать **«Найден по GUID, артикул отличается»** с ID Битрикс и обоими артикулами; **не обновлять** и **не менять артикул** автоматически.
- Если у найденного товара заполнен другой GUID — блокировать автоматическую перезапись и отправлять на ручную проверку.
- Если GUID совпадает, товар всё равно допускается к обновлению цены и согласованных полей.
- При нескольких проблемах у строки показывать основной статус и дополнительные причины. При любом блокирующем конфликте ничего не изменять.

### Статусы предварительной сверки

- Готов к обновлению (GUID нужно привязать).
- GUID уже совпадает (остальные поля всё равно обновляются).
- Другой GUID — ручная проверка.
- Дубль артикула в Excel / 1С.
- Дубль артикула на сайте (в причине указать количество найденных элементов).
- Найден по GUID, артикул отличается (ID и оба артикула; блокирующий конфликт).
- GUID занят другим товаром (в том числе когда GUID принадлежит иному найденному по артикулу товару).
- Не найден на сайте.
- Нет артикула.
- Ошибка значения ячейки (колонка и причина).
- Исключён при подготовке (причина: цена 0, пустая цена, пустой артикул и т. п.).
- Числовой артикул: проверьте возможную потерю ведущих нулей (**предупреждение**, не блокирует само по себе).

Пустую, нулевую или некорректную цену считать **блокирующим условием для всей записи**: не обновлять GUID, цену, флаги или остаток. Отдельная проверка удаления товара не нужна: если поиск по артикулу не находит элемент, используется статус «Не найден на сайте».

## 6. Обновляемые поля

Для каждой успешно сопоставленной, разрешённой к записи позиции:

| Поле | Действие |
|---|---|
| `XML_ID` | Установить GUID из Excel, только если текущий GUID пуст; при совпадении не переписывать |
| Базовая цена | Обновить из Excel, валюта `RUB` |
| `ACTIVE` | Установить `Y` |

Название товара в Битрикс **не менять**: название из Excel используется для сверки и отчёта. Родительские товары с SKU не трогать. При ошибке записи любого поля не помечать товар как полностью успешный; фиксировать фактический результат, включая возможное частичное обновление.

- Колонка **«Статус»** объясняет результат сверки; существующая колонка **«Результат»** до записи показывает **«К обновлению»** или **«Пропустить»**, после обработки — фактические **«Обновлено»**, **«Пропущено»**, **«Ошибка»**. Ещё не обработанные разрешённые строки остаются «К обновлению». Новую колонку для этого не создавать.
- В интерфейсе допускается скрытие ненужных исходных колонок без влияния на XLSX.
- На этом этапе **никаких изменений в Битрикс**.

## 8. Обновление и управление процессом

- Пакет — **до 25 разрешённых к записи строк**. Каждый пакет запускается **только отдельным нажатием** кнопки: «Обновить первые 25», затем «Обновить следующие 25» (или фактическое число оставшихся).
- **Никакого автоматического продолжения** и кнопок «Пауза / Продолжить». Без cron, фонового обработчика, очередей и дополнительных сервисов.
- **Остановить:** прекратить запуск новых пакетов; уже завершённые записи не откатываются. Требуется подтверждение. При закрытии браузера новый пакет не запускается; уже отправленный запрос может завершиться.
- Показывать процент, обработано, успешно, пропущено, ошибки, осталось. Сохранять результаты после каждого пакета; повторно не обрабатывать завершённые строки.
- По окончании последнего пакета корректно показывать завершённое состояние, не отправлять лишний запрос и **не показывать ошибку «Нет подготовленного плана»** из-за окончания обработки. Итоговый отчёт остаётся доступным.
- Защита от **одновременного второго запуска для одного сайта** должна быть серверной. Для двух сайтов задания независимы.
- При сбое/обрыве сохранять доступный прогресс; неопределённые операции перед повтором проверять по фактическим данным. Ошибка отдельного товара фиксируется, остальные продолжаются. При невозможности безопасно сохранять состояние — прекращать запуск новых пакетов.
- Перед записью повторно проверять критичные условия сопоставления, чтобы не перезаписать конфликтующий GUID. Нельзя считать запись успешной до подтверждения результата.
- Автоматическое управление обменом 1С и автоматический откат всего каталога не делать.

## 9. Файлы на скачивание

**Три потенциальных XLSX в полном сценарии:**

1. **Подготовленный Excel** — необязательная загрузка после этапа подготовки; только оставшиеся строки, исходные колонки.
2. **Предварительный отчёт XLSX** — все исходные строки и колонки, включая исключённые при подготовке, плюс данные и статусы сверки Битрикс.
3. **Итоговый отчёт XLSX** — то же, плюс фактический результат записи: успешно / ошибка / частично / пропущено / не обработано, с причинами.

Таким образом, **два отчёта сверки/обновления**, как согласовано ранее, плюс **отдельный необязательный файл очищенного Excel**. Отдельный CSV и отдельный файл ошибок не нужны.

- Добавленные колонки визуально отделить от исходных.
- Удобная цветовая индикация: успешные — зелёный, конфликты/пропуски — жёлтый, ошибки — красный.
- **До начала обновления** показывать только кнопку «Предварительный XLSX». **После начала обработки** показывать также «Итоговый XLSX»; он доступен при остановке и после завершения. Предварительный отчёт остаётся неизменяемым снимком до записи; итоговый отражает фактические результаты, необработанные позиции явно отмечены.
- Не удалять исходные строки из отчётов сверки и обновления, даже если они исключены из рабочего набора на этапе подготовки.

## 10. Надёжность и ограничения

- Проверить соответствие свойств/полей фактической конфигурации двух сайтов, особенно `KOD_IZ_1C`, цены и остатков у SKU.
- Не допускать смешивания данных разных сайтов и заданий.
- Соблюдать права доступа и защиту административного действия от посторонних запросов.
- Проверить лимиты памяти/времени на больших XLSX; не загружать всю таблицу результатов в браузер одновременно.
- Сохранять отчёт о фактическом результате каждой записи, не маскировать частичную запись как успех.
- Не обещать атомарности многополевого обновления: если операция прервалась, показать фактическое состояние и обеспечить безопасную повторную проверку.
- Проверить корректность обработки артикулов с ведущими нулями и смешанными текстовыми/числовыми типами ячеек.

## 11. Порядок реализации и приёмки

1. Получить и изучить исходный архив `bitrix-guid-tool-v1.11.zip`, определить используемые библиотеки и ограничения окружения.
2. Спроектировать и реализовать отдельную базовую реализацию с понятным разделением подготовки Excel, сверки, обновления и отчётности; переносить из v1.11 только проверенные решения.
3. Реализовать загрузку, сопоставление колонок и подготовку XLSX.
4. Реализовать полную сверку, статусы, поиск, фильтры и пагинацию.
5. Реализовать безопасное пакетное обновление, управление и сохранение прогресса.
6. Реализовать три скачиваемых XLSX по описанным правилам.
7. Проверить на тестовом файле: нулевая/пустая цена, пустой артикул, артикул с пробелами, дубли, GUID-конфликт, SKU, совпадающий GUID, сбой посреди пакета, повторный запуск.
8. Сначала выполнить сверку без записи, затем контролируемый тест на 5–10 товарах, после проверки — массовое обновление.

**Следующий шаг:** провести тесты сборки 1.1.0 на стенде Битрикс с контролируемым XLSX и резервной копией.

## 13. История обновлений — реализовано в тестовой сборке 1.1.0

- При первом запуске записи создавать отдельную запись истории с уникальным ID запуска, датой/временем начала, выбранным сайтом и ID администратора.
- Сохранять прогресс после каждого пакета, включая **незавершённые** запуски; фиксировать время завершения, статус («Завершено», «Не завершено», «С ошибками»), число обновлённых, пропущенных и ошибок.
- Сохранять **отдельный итоговый XLSX для каждого запуска** в закрытом серверном хранилище, не перезаписывая прошлые отчёты. Для незавершённого запуска обеспечивать скачивание отчёта с фактическим прогрессом.
- На странице инструмента показывать раздел «История обновлений» с фильтрацией/разделением по сайту, датой, администратором, статистикой и скачиванием XLSX.
- **Бессрочное хранение**, без автоматической очистки. Ручное удаление выбранных записей и их файлов только администратором, с подтверждением. Удаление истории **не изменяет товары Битрикс**.
- Исключить публичный доступ к файлам отчётов; проверять права при скачивании и удалении. Учесть ограничения места на диске и ошибки сохранения.

## 14. Возможный функционал в будущем — НЕ согласован к реализации

1. **Коррекция артикула на сайте по GUID.** Для случая «Не найден на сайте; GUID занят другим товаром: 267915» или «Найден по GUID, артикул отличается» рассмотреть предложение изменить артикул соответствующего товара Битрикс на значение из Excel. До реализации согласовать права, подтверждение, защиту от дублей и проверку, что GUID действительно принадлежит нужному товару. **В текущей версии ничего не менять автоматически.**
2. **Пустой артикул в Excel: поиск по GUID или коду 1С.** Рассмотреть резервную логику сопоставления при пустом артикуле: сначала проверка по GUID, либо по коду 1С при наличии однозначного соответствия. Требуется согласовать источник/колонку кода 1С, приоритеты, обработку конфликтов и запрет неоднозначной записи. **Сейчас строку с пустым артикулом не обновлять.**

## 15. Статус реализации

**Тестовая сборка 1.1.0 реализована в PHP-коде**, но пока не проверена на живом Битрикс и в интеграционных XLSX-тестах. Название проекта и папки: `bitrix-guid-tool` (без версии); прежняя предварительная сборка `v2.0-preview` соответствует базе 1.0.0 новой линейки. ## 14. Требования версии 1.1.1

1. Подготовка: две галочки — `drop_price` и `normalize`; не исключать строки с пустым артикулом; не удалять дубли. Кнопка проверки не создаёт XLSX, кнопка применения создаёт новый XLSX, прямая сверка обходит подготовку.
2. Всегда считать статистику исходного Excel: total, zero_price (нулевая или пустая), empty_article, normalized (пробелы по краям), duplicates (количество строк, не уникальных артикулов). Независимо считать kept и total-kept по текущим настройкам.
3. На странице подготовки показывать все строки с повторяющимся артикулом в отдельной таблице: номер строки исходного Excel, артикул, GUID Excel, цена Excel. Поиск по артикулу, 100 строк на страницу, скачать XLSX с оригинальными колонками и номером строки. Никаких изменений исходного файла.
4. Предварительный вывод: Строка | Артикул Excel | Название Excel | GUID Excel | Цена Excel | ID сайта | Тип | Название сайта | XML_ID сайта | Статус | Причины | Результат. Название Excel берётся из выбранной колонки `name`; пустые поля сайта при отсутствии найденного товара допустимы. Структура одинакова для всех статусов и фильтров.
5. Существующая диагностика GUID для дублей и пустых артикулов сохраняется; автоматическое обновление таких строк запрещено. Изменение артикула на сайте, выбор товара только по GUID и двухуровневая шапка не входят в 1.1.1.
6. Версия приложения — 1.1.1; папка проекта — `bitrix-guid-tool`.


## 16. Реализованные изменения версии 1.1.2 (приоритет над устаревшими требованиями выше)

1. **Подготовка:** после «Применить подготовку» оставаться на той же странице, показывать настройки, статистику исходного Excel и число дублей. Ниже — кнопки скачивания подготовленного XLSX и полной сверки без записи. Допускается повторное применение подготовки до сверки.
2. **Состав сверки:** после применения подготовки исключённые по цене строки не передаются в таблицу сверки и не попадают в предварительный/итоговый XLSX; счётчики строятся только по оставшимся строкам. Статистика исходного файла и число исключённых сохраняются в сохранённом задании. При прямой сверке без подготовки включаются все исходные строки.
3. **Дубли:** под статистикой только количество строк с повторяющимися артикулами и скачивание XLSX. Без экранной таблицы, поиска и пагинации. XLSX дублей: `Артикул Excel | Название Excel | GUID Excel | Цена Excel`. Дубли не удалять и не разрешать к обновлению; GUID продолжать проверять для диагностики.
4. **Номера строк:** служебный столбец «Строка» убрать из экранных таблиц, новых предварительных/итоговых XLSX и выгрузки дублей. Номер исходной строки сохранять во внутренних данных. Существующие архивные XLSX прошлых версий не переписывать.
5. **Верх страницы:** один заголовок `Bitrix GUID Tool 1.1.2` через заголовок админки; раскрывающаяся история версий, получаемая из `CHANGELOG.md` (новая версия раскрыта, старые свёрнуты); отдельный раскрывающийся справочник статусов и решений.
6. **Статусы:** точные названия брать из `Core::plan()`, не придумывать новые; показывать разрешённые (`Готов к обновлению`, `GUID уже совпадает`) и блокирующие статусы с пояснениями. Первый блокирующий пункт — основной статус, остальные — в «Причинах». Для динамических статусов с ID сохранять префикс и отображать конкретные значения в рабочей таблице.
7. **Не менять:** сопоставление по артикулу, диагностику по GUID, правила запрета, поведение XML_ID=`0`, обновляемые поля, ручные пакеты по 25 и хранение истории обновлений.

Разделы выше, описывающие показ исключённых строк в сверке, таблицу дублей, 12-колоночную таблицу с номером строки и старые опции подготовки, относятся к историческим требованиям и заменены настоящим разделом.

## Уточнение 1.1.7 — фильтрация журнала сверки

- «Все проблемы» по умолчанию показывает строки с исходным результатом «Пропустить», в том числе строки со статусами №1/№2, заблокированные проверкой артикула-даты.
- Выпадающий фильтр предлагает все 9 статусов, включая №1 «Готов к обновлению» и №2 «GUID уже совпадает». По умолчанию «Все проблемы» показывает только строки с исходным решением «Пропустить». При выборе статуса показываются все строки этого статуса независимо от результата.
- Поиск применяется ко всем строкам выбранного статуса, а в режиме «Все проблемы» — ко всем проблемным строкам. Ограничение 200 строк действует только после поиска и фильтрации.
- Полный предварительный XLSX содержит все строки без ограничения 200.
- При пакетном обновлении для журнала используется исходное решение о пропуске, а не изменившийся результат выполнения.
